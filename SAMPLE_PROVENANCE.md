# Provenance of reused sample code

ClaimSense AI reuses the Week 15 course sample ("The Meridian Engagement") as its starting skeleton,
as planned in `docs/ClaimSense-AI-Reuse-Plan.pdf`. This file records exactly what was copied, so every
later change shows up as a diff against the original.

- **Source:** `IK-Sessions/Week-15/ik-fde/codebase`, git commit `4ed3a5f` (2026-10-18), authored by the
  IK FDE curriculum (the agent package declares an MIT licence in `agent/pyproject.toml`).
- **Copied:** 2026-10-26, verbatim (no edits) in the commit that adds this file.
- **Checked after copying:** the sample's offline smoke gate passes (`make eval` equivalent, 100%) and
  its 15 unit tests pass (`uv run --extra dev pytest`).

## What was copied, and where it went

| Source (`codebase/…`) | Destination | Planned use |
|---|---|---|
| `Makefile` | `Makefile` | Same targets (up, web, agent, eval, golden, verify, doctor, down) |
| `platform/db/` (schema, api.sql, compose, loader, key minting, seed generator) | `platform/db/` | PostgreSQL for the three client systems plus ClaimSense |
| `platform/web/` (Next.js console and `/api/v1`) | `platform/web/` | Adjuster console and data API |
| `agent/` (`meridian_agent` package, tests, golden-suite tooling) | `agent/` | ClaimSense agent package |
| `deploy/ec2/` | `deploy/ec2/` | EC2 deployment |
| `labs/w15-build/demo/` `common.py`, `demo2_pipeline.py`, `README.md`, `.env.example`, `data/fixture.json`; `labs/w15-build/test_bedrock.py` | `reference/w15-bedrock-demo/` | Reference for the Agents SDK + Claude on Bedrock pattern (kept as reference, not run in CI) |
| `labs/w15-build/eval-gate.yml` | `ci/eval-gate.yml` | CI gate template; **inactive** until adapted and moved to `.github/workflows/` |

## Deliberately not copied

- Secrets and local settings: `.env`, `.env.local`, `aws.env` (only `.env.example` templates came across, with placeholder values).
- Build and install output: `node_modules/`, `.next/`, `.venv/`, `__pycache__/`.
- `platform/db/seed/data/` (11 MB of generated Meridian CSVs; regenerated by `seed/generate.py`, and to be replaced by the course fixtures).
- The sample's other labs, notebooks, docs and `evidence/` outputs (Meridian-specific; the evidence convention will be followed, not the files).

## Adaptation log

1. **Product and package rename (done):** Meridian → ClaimSense in package, CLI, environment
   variables, database name/user/container/volume, Postgres schema prefix, Tailwind colour tokens,
   EC2 names and prose; seed e-mail domains → `autosure.test`. `agent/src/meridian_agent` became
   `agent/src/claimsense_agent` (`claimsense-agent` CLI). Behaviour unchanged: the smoke gate and the 15
   unit tests pass, the lock file is consistent, the console type-checks and builds. `reference/` and
   this file keep the original names on purpose.
2. **Database schema and loader (done):** `platform/db/schema.sql` replaced with the ClaimSense
   schema (four schemas: `claims_mgmt`, `policy_admin`, `doc_store`, `claimsense`; see
   `docs/ClaimSense-AI-Schema-ER-Diagram.pdf`). The sample's `seed/generate.py` (Meridian bank
   generator) was removed; `seed/build_seed.py` builds CSVs from `data/course_fixtures` and
   `data/identity/users.json`, and its load-time guardrail (`seed/guardrail.py`) quarantines the
   injected chunk in `seed/injected_clauses.json`. `load.sh` keeps the sample's structure (build CSVs,
   reset, `\copy`, sanity counts). The local database now uses host port 5433 so it can run beside a
   local PostgreSQL on 5432. `api.sql`, `mint-key.mjs` and the `keys` target are legacy Meridian API-key
   pieces, no longer part of `make up`; they go when the API moves to Cognito.
3. **Data API as a Python service (in progress):** by decision, the gatekeeper is a new Python
   (FastAPI) service in `api/`, not the sample's TypeScript API. Its `auth.py`, `access.py`, `audit.py`
   and error responses are Python ports of the sample's `auth.ts`, `scope.ts`, `audit.ts` and
   `respond.ts`, with two deliberate changes: an unknown claim gets the same 403 as a forbidden one
   (the sample returned 404), and refusal messages never give the reason (the sample did).
4. **Console on the Python API (done):** the console keeps the sample's layout, sidebar, panels and
   styling; its TypeScript API routes, database code, bank pages and charts were removed. Pages now
   call the Python data API with the signed-in user's token (development sign-in through the API).
   The `agent/` package is still the sample's dispute pipeline and is replaced when the agents are built.
5. **Earlier note (superseded):** the console, API routes and the agent's live database path
   still expect the old Meridian tables, so they will not work against the new database until adapted
   (the agent's offline `--mock` path and tests still pass).
4. **Earlier note on what remained:** tables, routes and logic are still disputes, Reg E rules and
   scoped API keys, and some prose reads "ClaimSense Bank". Adapting them to claims, the AutoSure manual,
   the course data, Cognito and the MCP server follows the reuse plan, in separate commits.
