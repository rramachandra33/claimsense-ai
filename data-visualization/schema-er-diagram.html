Proposed PostgreSQL schema for the course data: the three client systems the MCP server serves, and ClaimSense's own tables for drafts, retrieval, idempotency and audit. Key columns are shown; full definitions are in the schema proposal. Not yet written to platform/db.

Rules the schema enforces

Bad chunk never loadsIt lives in policy_clauses as the client system exposes it. The loader's guardrail sends each clause to exactly one of clause_index or clause_quarantine; agents can only search the index.
Pending documents have no textocr_text must be null unless ocr_status is Completed (CLS-DOC-009).
Notes need citationsA claim note must cite clauses, unless it is a DENY with a reason such as "no supporting clause found".
Retries never double-writeidempotency_keys returns the stored note for the same key and payload, and 409 for a different payload.
Not stored on purposeExpected outcomes and labels stay out of the database; code facts are recomputed each run and saved inside assessments.
Two vehicle records, by designClaims management and policy administration each keep their own VIN, vehicle and ACV, as separate client systems do. Payout uses the claim's ACV at the time of loss (CLS-COLL-001); code compares the two on every run, and a mismatch becomes evidence for a FLAG rather than a load error.
Every call is auditedaudit_log records the user, who acted (human or agent), on whose behalf, and allow or deny with the reason.
